JavaScript Fundamentals

Hoisting

Understand how JavaScript handles declarations before code execution and why function declarations, var, let and const behave differently.

Intermediate Execution Interview Essential
Definition Syntax var let & const Functions Examples Real Life Interview Challenge
01

Foundation

What is hoisting?

?

What?

Hoisting describes JavaScript's behavior of processing declarations during the creation of an execution context before executing the associated code.

⏱

When?

Hoisting is relevant whenever JavaScript encounters variable, function, class or module declarations during execution.

💡

Why?

Understanding hoisting helps explain why some identifiers can be referenced before their declaration while others produce an error.

⚙

How?

Before executing statements, JavaScript creates an execution context and establishes bindings for relevant declarations. The exact behavior depends on the type of declaration.

02

Fundamentals

Basic idea of hoisting

JavaScript 
console.log(name);

var name = "Amit";

// Output:
// undefined


greet();

function greet() {

    console.log("Hello");

}

// Output:
// Hello
Important: Hoisting does not literally move your source-code lines to the top. It describes how declarations are handled during execution-context setup.
03

Variable declarations

Hoisting with var

Example 01

var is hoisted and initialized with undefined

A var declaration is processed before the execution of the surrounding code, and its initial value is undefined until the assignment executes.

JavaScript 
console.log(score);

var score = 100;

console.log(score);

// undefined
// 100
Concept

Declaration vs assignment

It is useful to mentally separate the declaration from the assignment when understanding var hoisting.

Conceptual model 
var score;

console.log(score);
// undefined

score = 100;

console.log(score);
// 100
04

Block-scoped declarations

Hoisting with let and const

Example 02

Temporal Dead Zone

let and const bindings are created when their scope is initialized, but they cannot be accessed before the declaration is evaluated. This period is called the Temporal Dead Zone, or TDZ.

JavaScript 
console.log(name);

let name = "Amit";

// ReferenceError
Example 03

const behaves similarly

A const declaration also cannot be accessed before its declaration is evaluated.

JavaScript 
console.log(age);

const age = 25;

// ReferenceError
⚠

Interview tip: Do not say that let and const are "not hoisted." Their bindings are established during scope initialization, but accessing them before initialization results in a ReferenceError because of the Temporal Dead Zone.

05

Function declarations

Function hoisting

Example 01

Function declarations

Function declarations are available before their position in the source code within the applicable scope.

JavaScript 
greet();

function greet() {

    console.log("Hello JavaScript!");

}

// Hello JavaScript!
Example 02

Function expressions behave differently

When a function is assigned to a variable, the behavior depends on how that variable is declared. A function expression assigned to var cannot be called before the assignment has executed.

JavaScript 
greet();

var greet = function () {

    console.log("Hello");

};

// TypeError:
// greet is not a function
Example 03

Arrow functions are not callable before initialization

An arrow function assigned to a const variable cannot be called before the declaration is evaluated.

JavaScript 
greet();

const greet = () => {

    console.log("Hello");

};

// ReferenceError
06

Learn by doing

Common hoisting examples

Example 01

var inside a function

The var declaration is scoped to the function and is initialized as undefined before execution reaches the assignment.

JavaScript 
function example() {

    console.log(value);

    var value = 50;

    console.log(value);

}

example();

// undefined
// 50
Example 02

let inside a block

Accessing a let binding before its declaration is evaluated results in a ReferenceError.

JavaScript 
if (true) {

    console.log(message);

    let message = "Hello";

}

// ReferenceError
Example 03

Function declaration

A function declaration can be called before its declaration appears in the source code.

JavaScript 
calculate();

function calculate() {

    console.log("Calculation started");

}

// Calculation started

Practical JavaScript

Real-life use case

Code Organization

Understanding legacy JavaScript code

Hoisting becomes especially useful when maintaining older JavaScript applications that use many var declarations and function declarations. Understanding the execution behavior helps explain unexpected values and errors.

JavaScript 
function initializeApp() {

    setup();

    console.log(status);

    var status = "Ready";

    function setup() {

        console.log("Application setup");

    }

}

initializeApp();

// Application setup
// undefined
💡

Best practice: Do not rely on hoisting to make code work. Declare variables before using them and organize code so that its execution order is easy to understand.

08

Interview preparation

Top 5 interview questions

01 What is hoisting in JavaScript? +

Hoisting describes how JavaScript processes declarations during execution-context setup before executing the statements in that context. Different declaration types have different behavior.

02 Are let and const hoisted? +

Their bindings are created during scope initialization, but they remain inaccessible until their declarations are evaluated. Accessing them before that point causes a ReferenceError because of the Temporal Dead Zone. 

console.log(value);

let value = 10;

// ReferenceError
03 What happens when var is accessed before declaration? +

The var binding is initialized to undefined, so accessing it before its assignment produces undefined. 

console.log(value);

var value = 10;

// undefined
04 Why can a function declaration be called before it is defined? +

Function declarations are instantiated during execution-context creation, including their function body, so they can generally be called before their source-code position within the same applicable scope. 

greet();

function greet() {

    console.log("Hello");

}

// Hello
05 What is the Temporal Dead Zone? +

The Temporal Dead Zone is the period from entering the scope of a let, const or class declaration until that declaration is evaluated. Accessing the binding during this period throws a ReferenceError. 

{
    // TDZ starts here

    console.log(name);

    const name = "Amit";

    // TDZ ends when declaration is evaluated
}

Remember

Hoisting explains declaration behavior, not magical code movement.

Remember the key differences: var is initialized to undefined, let and const remain inaccessible during the Temporal Dead Zone, and function declarations can generally be called before their declaration.
